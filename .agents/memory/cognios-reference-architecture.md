name: CogniOS reference architecture
description: Durable content and interaction rules for presenting the CogniOS architecture.
---

Use the stable six-layer model in this order: Experience, Intelligence, Process, Knowledge, Integration, and Foundation, with AI Governance & Assurance and Platform Engineering & Operations as cross-cutting spines. The platform overview should explain this spatially; the dedicated architecture route should provide layer → component → detail exploration.

**Why:** The original source contains the intended structural hierarchy but also mixes in maturity labels, deployment guarantees, localisation promises, and other assertions that are not approved as production claims.

**How to apply:** Preserve responsibilities, relationships, and the two-level drill-down. Frame components as a reference architecture, and omit unsupported status, sovereignty, compliance, language, deployment, recovery, and capability guarantees.
